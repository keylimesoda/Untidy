## What changed

- Rebuilt the home screen around Search, Recent, and a persistent Now Playing path when a session exists.
- Preserved album and playlist context in Recent instead of reducing listening history to tracks.
- Repaired external-route and back-stack behavior across home, Now Playing, artist, album, and deeper collection navigation.
- Reworked v2 search request parameters, added legacy supplementation for partial track-only responses, restored artists/albums/playlists, and filled missing track metadata and artwork.
- Refined the Now Playing pull-up interaction with a guarded grip, a short first-use hint, an integrated action surface, and a direct Home action.
- Replaced the generic audio-route handoff with an in-app list of available outputs, including the watch speaker and connected Bluetooth devices.
- Added working track and album favorite controls with optimistic UI, TIDAL collection writes, haptic confirmation, and rollback on failure.
- Added an opt-in Full fidelity preset with HiRes FLAC, FLAC, and AAC fallback requests.
- Added a TIDAL-style, quality-colored playback badge based on the format actually delivered to the player.
- Enabled an explicit Download over LTE preference while retaining battery-safe background-work constraints.
- Reduced repeated API/network work through shared connections, favorite caching, cancellation-safe fallback behavior, paged relationship reads, bounded queue lookahead, and narrower artwork requests.
- Reduced UI work by limiting live position polling to visible, interactive Now Playing and suppressing it in ambient/background surfaces.

## Physical-watch validation

Validated on a Samsung Galaxy Watch6 LTE (`SM-R955U`):

- Search returns mixed entity groups and track artwork for the tested Moby query.
- Album → Now Playing → artist → deeper album → Back returns through the expected stack without a black-screen dead end.
- Re-entering Now Playing reuses the existing player activity instead of creating duplicate stacks.
- Track and album favorite writes succeed against the authenticated TIDAL account; validation toggles were restored afterward.
- Album favorite placement does not move or obscure album art.
- Playback can remain paused after navigation and validation.

## Battery and performance status

This build includes a substantial code-level power pass, but it is not the final endurance sign-off.

- Playback uses Media3/ExoPlayer and Android's MediaCodec path.
- Battery Saver requests efficient AAC, queue lookahead is bounded, offline playback uses local wake behavior, and interactive progress polling stops when it is not needed.
- Download work requires a non-low battery and uses unmetered networking unless the user explicitly enables LTE.
- The codec profiler and tier resolver are not yet connected to runtime stream selection, so hardware decoding is not currently proven or enforced.
- Full fidelity may use software FLAC on watches without a hardware FLAC decoder and can consume considerably more battery and data.
- A controlled screen-off Bluetooth/speaker × AAC/FLAC × Wi-Fi/LTE Batterystats/Perfetto matrix remains open.

## Reddit-ready announcement

### Title

**Untidy 0.6.0 beta 5: a much smoother standalone TIDAL app for Wear OS**

### Post

I've been giving Untidy—the unofficial, standalone TIDAL client for Wear OS—a fairly ruthless usability pass, and beta 5 is the first build where the whole thing is starting to feel cohesive instead of merely functional.

The biggest change is navigation. Back now behaves like navigation instead of occasionally launching you into the void. You can move from an album into Now Playing, pull up the action sheet, browse the artist or another album, and unwind the same path. There is also a direct Home action for the times when you have wandered several layers deep, while Home keeps a Now Playing entry so your music is never hard to recover.

Search got a substantial repair too. It now uses TIDAL's v2 request shape correctly and supplements incomplete responses, so a search can show artists, albums, playlists, and tracks—with the missing artwork and metadata filled back in—instead of degenerating into a sad list of track names.

Now Playing has a new guarded pull-up interaction, a cleaner action menu, an in-app audio-output picker that lists the watch speaker and connected Bluetooth outputs, a real working Like button, and a little TIDAL-style quality gem showing the format actually delivered. Albums now have their own working heart in the same visual position as Now Playing.

There is also an opt-in Full fidelity mode. It asks for HiRes FLAC, then FLAC, and falls back to AAC when necessary. It is deliberately not the default: lossless on a tiny watch can be expensive in both data and battery, especially when the device only has a software FLAC decoder.

Other less glamorous but important work includes collection-aware Recent history, an LTE-download opt-in, bounded playback lookahead, fewer repeated API calls, smaller artwork work, and position polling that shuts down when Now Playing is hidden or ambient.

This has been built and exercised on a Galaxy Watch6 LTE. The new navigation paths, mixed search results, playback controls, and track/album favorite writes have all had real-watch validation. The next serious engineering pass is measured battery testing and wiring runtime codec capability detection into stream selection; I don't want to make heroic battery claims without numbers.

Untidy is still an unofficial prerelease and is not affiliated with TIDAL, Google, or Samsung. If you try it, the feedback I want most is: where does the app still make you stop and think, which audio route/quality combination are you using, and what does a normal listening session do to your battery?
